# [M3.4] Add a catastrophic-forgetting regression benchmark

**Closes:** [#289](https://github.com/DPBG/Engram.AI/issues/289)

**Branch:** `feat/issue-289-catastrophic-forgetting-benchmark`

## Summary

- Add `CatastrophicForgettingBenchmark`: train stimulus set A → train set B → re-probe A with `training_reps=0`.
- Measure retention with `ConceptSeparabilityBenchmark`'s `separation_ratio` on A's stimuli after B (the failure mode the issue flags).
- Mid-protocol capture of `network.get_state()` — the same dict `NeuromorphicPersistence.save_state` writes — without restoring before the A re-test (restoring would undo B and hide forgetting).
- Wire into `BenchmarkSuite.run_all()` / `summary()` as an additive top-level key (`catastrophic_forgetting`).

## Why

Invariant 6 claims homeostatic scaling prevents catastrophic forgetting, but that was only exercised by short-horizon weight-correlation unit tests (`TestContinualLearning.test_pattern_retention`). None of the suite benchmarks ran a train-A → train-B → re-test-A protocol.
